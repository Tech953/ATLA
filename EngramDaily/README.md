# Engram Daily — Jade edition

A native Android starter app for a daily career digest, user-defined character companions, local GGUF inference and API inference. **Jade**, adapted from Beck Duston's *The Long Tar*, is the default editable engram. Any career can be entered; no personal identity or career is hard-coded into the user's profile.

## Build in Android Studio

1. Extract this directory and open it in Android Studio.
2. Select **JDK 17** for Gradle. Install **Android SDK Platform 35**, **Build Tools 34.0.0**, **NDK 27.0.12077973**, and **CMake 3.22.1** through SDK Manager. Accept the required licenses.
3. Sync Gradle. The Gradle wrapper is included (8.9 with distribution checksum); Android Gradle Plugin is 8.7.3. Initial dependency downloads require internet.
4. Select an arm64 device or x86_64 emulator running Android 9 / API 28 or newer, and Run.
5. To build from a terminal: `./gradlew :app:assembleDebug` (Windows: `gradlew.bat :app:assembleDebug`).
6. The installable test APK will be `app/build/outputs/apk/debug/app-debug.apk`.

`local.properties` is generated by Android Studio. For command-line builds, set `ANDROID_HOME` to your SDK directory or write `sdk.dir=/absolute/path/to/sdk` in `local.properties`.

llama.cpp b5046 is bundled as a checksum-pinned source archive, compiled into the APK with JNI. No model server or companion app is needed. CPU inference is supported for arm64-v8a and x86_64. Model weights are **not** bundled: import a separately obtained, licensed, compatible text-instruct GGUF. Older runtime versions do not support every new model architecture or template. The native library is configured for 16 KB page alignment; verify the final release APK on target devices.

## Install the provided test APK

The separate `Engram-Daily-Jade-0.1.0-test.apk` is an actual debug-signed APK. Its Gradle build and APK signature verification succeeded. Open it on Android 9 or newer and permit installation from the source you used to download it. No device runtime testing has been performed. The source ZIP is for development and is not installable.

## First run

1. **Profile**: enter any career, goals, constraints and optional memory. Paste or import a short reference excerpt with source names, URLs and dates. Save before changing tabs.
2. **Engram**: Jade is preloaded. Edit the bio or import another schema-v1 character JSON. Save before starting a conversation.
3. **Settings**: choose Planner, GGUF or API and save. Planner needs neither internet nor model weights.
4. **Today**: generate a digest. Share through Android's share sheet or export a text file.
5. **Lab**: log practice, inspect seven-day totals, calculate effort scenarios or use the companion for a simulated career situation.
6. **Settings → Daily delivery**: choose device-local HH:mm and enable the schedule. Permit notifications when Android asks. Android controls the actual background execution time; force-stopping the app suppresses jobs until reopened. If jobs fail, Today displays the last error.

## Engine modes

| Mode | Behavior | Data leaving the device |
| --- | --- | --- |
| Planner | Clearly labeled deterministic daily planning template | None |
| GGUF | Embedded llama.cpp generates from imported model and saved inputs | None |
| API | HTTPS POST to a user-configured chat-completions-compatible endpoint | Profile, constraints, memory, reference notes, bio, task; recent saved exchanges for chat |

API setup takes the **complete endpoint URL**, provider model identifier and optional bearer key. It expects a non-streaming `choices[0].message.content` string response and supports the `max_tokens` parameter. Providers with different schemas, required extra headers or only a Responses-style API need an adapter. HTTP and redirects are rejected. No provider or endpoint is preselected. Choose an endpoint you intend to receive the data; enabling the schedule in API mode permits those configured daily requests and their provider charges. Revoking API data sharing blocks new API generation after settings are saved.

Local prompts use the model's embedded supported chat template, a 2,048-token context and a 384-token output cap. Inputs that exceed the budget produce an explicit error, not silent truncation. Generation has a roughly 100-second cooperative deadline, including model loading; a smaller quantized model is more practical on constrained phones. Large or malformed models may still exhaust memory and cause Android to terminate the process. Hardware/model performance needs device testing.

## What this version includes

- Any career and user-editable goals, values and constraints.
- Jade baseline character, custom engram JSON import/export.
- Real API request path and native on-device GGUF inference implementation.
- Manual and scheduled digests, local notifications and user-initiated sharing.
- User-edited memory; optional saved chat exchanges. Unsaved exchanges are not retained or included in later conversations.
- Practice logging, seven-day totals, CSV export, deterministic effort projections, and AI-assisted scenario rehearsal.
- Personal-data JSON export, conversation deletion and full app-data erasure.
- Android Keystore encryption for the API key, private local app storage, disabled Android backup, and no analytics SDK or trackers.

## Scope and known limits

This is an initial implementation, not an unlimited analytics platform. Analytics currently cover user-entered practice logs and explicit hours/week × weeks × adherence scenarios. AI scenarios are qualitative exercises, not validated predictions. It does not measure brain changes or provide neural monitoring.

Reference text is pasted or imported (`.txt` / `.md`, up to 6,000 characters); there is no live-news crawler, social account integration, full-document retrieval or automatic job-board ingestion yet. Offline material can be stale. No money movement, bill payment, account login, autonomous messaging or external tool execution is implemented. Distribution is local notifications plus deliberate export/share; no recipient is contacted automatically.

Profiles/history are private app files, not a separately encrypted database. API keys are encrypted. Exports exclude API settings, keys and model weights. JSON exports are for portability/readability; full backup restore is not implemented. Histories and practice logs each retain the latest 100 entries; seven-day totals therefore reflect the retained log. Routine Android lifecycle/process termination can interrupt generation. Save edits before switching tabs or leaving the app. GGUF native output is returned after completion, not streamed.

The engram can be replaced, but model compliance with its character and boundaries is probabilistic. System prompts set expectations; the app gives models no action tools. The built-in planner does not perform inference and is labeled accordingly.

## Self-publish a signed APK

Use **Build → Generate Signed Bundle / APK → APK** in Android Studio. Create and securely retain your own release keystore and choose the release variant. The project deliberately contains no signing key or signing passwords. A command-line `assembleRelease` without your signing configuration produces an unsigned release artifact.

Test the signed APK on the devices you intend to support; then distribute that APK through your own website or chosen channel. Users install it using Android's permission for installing from that source. Keep the same application ID and signing key for updates, and increment `versionCode`. Do not distribute the debug APK as your production release. Model redistribution requires checking the particular model's license; no model weights are included here.

## Source layout

- `app/src/main/java/dev/engram/daily/`: UI, storage, API inference, scheduling and calculations.
- `app/src/main/cpp/`: native GGUF bridge and CMake configuration.
- `app/src/main/assets/jade.engram.json`: bundled default character.
- `examples/jade.engram.json`: portable character file.
- `JADE_ADAPTATION.md`: canon versus adaptation and unresolved draft details.
- `tests/`: lightweight calculation and prompt-contract checks.
- `.github/workflows/android.yml`: optional build validation when placed in your GitHub repository. It does not publish a release.
- `VALIDATION.md`: what has actually been checked and what remains.
