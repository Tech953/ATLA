# Engram Daily — functionality audit and repair checkpoint

Date: 2026-09-28 UTC. Status: source repair checkpoint, not a release certification.

## Confirmed cause of reported file failure

Both supplied filenames begin with mmproj. The publisher identifies these as multimedia projectors, which must accompany a separate language model. They cannot generate chat independently. The old import code checked only the GGUF magic bytes; this allowed a projector to appear registered as a chat model. That was an application validation defect.

The bundled llama.cpp b5046 architecture table contains Gemma, Gemma 2 and Gemma 3 but not Gemma 4; it contains Qwen/Qwen2 variants but not the newer Qwen3.6 architecture. The existing binaries must not be represented as supporting these models. The application also has no image/audio input or separate projector loading path.

Publisher references:
- https://huggingface.co/HauhauCS/Gemma-4-E4B-Uncensored-HauhauCS-Aggressive
- https://huggingface.co/HauhauCS/Qwen3.6-35B-A3B-Uncensored-HauhauCS-Aggressive/raw/main/README.md
- https://github.com/ggml-org/llama.cpp/blob/master/tools/quantize/README.md

## Source changes completed

- Android and Windows now inspect bounded GGUF architecture metadata at import and before inference. Renaming a projector cannot bypass detection. Unsupported architectures receive an explicit runtime-upgrade error. Validation does not claim that tensors, quantization, memory fit or generation are verified.
- Both settings screens have a saved-engine/engram generation test. This sends the saved profile and persona through the actual generation path; API mode retains the existing sharing-consent requirement.
- Windows captures bounded engine startup diagnostics instead of discarding stderr. Model path and generated local API key are redacted in the exit error.
- Windows displays chat errors next to the reply and scrolls them into view.
- Windows retains recent unsaved conversation turns in RAM for subsequent prompts and clears them when conversations/data are deleted. Persistent history remains opt-in.
- Packaging includes the new Windows GGUF validator and runtime architecture table.
- Restored a truncated working-copy Android vendor archive from the intact saved source ZIP. Saved original archive passed CRC checks.

## Verification performed

- 14 Node automated tests passed (9 existing + 5 GGUF validation tests).
- Java GGUF validator compiled and exercised against supported metadata, renamed projector, unsupported Gemma/Qwen architectures and truncated input.
- Modified Windows main and UI JavaScript passed syntax checks.
- Both original source ZIPs passed CRC checks; updated source ZIPs checked again when packaged.

No real language-model generation, Windows installer execution, Android device run, native notifications, account authorization or live provider request was performed. Full application builds were not regenerated in this checkpoint. These limitations prevent calling the comprehensive repair complete.

## Release blockers and next decisions

1. Obtain exact ROG device/OS, RAM, GPU and VRAM. ROG is a product family and does not establish available memory. Obtain a full language-model filename in addition to any projector.
2. Upgrade and pin the native runtimes for the selected architecture; validate JNI/API changes, template formatting and quantization. Do not simply swap in arbitrary runtime binaries.
3. Verify end-to-end generation and persona continuity with a real model on each supported target, including no-network operation, insufficient memory, unsupported files, cancellation and restart.
4. Finish token-aware context management, Android session continuity and provider adapters.
5. Implement calendar OAuth with registered app client IDs, protected tokens, disconnect/revocation handling, calendar selection and recurrence/timezone tests against real provider data.
6. Rebuild APK/installer preserving Android signing identity, then test installation, persistence, scheduling and uninstallation on target devices before release.

The publisher lists the Qwen Q4_K_M language-model weights at about 21 GB and the mmproj at about 899 MB. File size is not total runtime memory; hardware suitability is not yet established. Do not download another projector as a replacement chat model.
